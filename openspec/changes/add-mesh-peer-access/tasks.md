# Tasks

Do not start implementation until the proposal has been reviewed. Scenario labels below are the titles in the delta specs; the snake_case names are the intended focused tests.

## 1. Mesh policy and authenticated ingress

- [ ] 1.1 Resolve the Kameo ingress choice and inventory remotely registered messages and actor lifecycle operations for LAN and Iroh. Define the minimum supported protected-sharing contract and authenticated local owner authority before exposing management operations.
- [ ] 1.2 Implement deny-by-default directional grants and authenticated origin propagation. Cover `mesh-peer-access / An admitted peer has no grant` (`an_admitted_peer_has_no_grant`) and `mesh-peer-access / Grant direction and identity do not change across scopes` (`grant_direction_and_identity_do_not_change_across_scopes`). Verify transport callers using separate processes/identities, not synthetic actor messages alone.
- [ ] 1.3 Implement the durable store and versioned owner API. Cover `mesh-peer-access / A peer cannot edit grants` (`a_peer_cannot_edit_grants`) and `mesh-peer-access / A stale owner edit is refused` (`a_stale_owner_edit_is_refused`). Include failure to persist and unauthenticated control requests in the same tests.
- [ ] 1.4 Add directional node reporting, scoped invalidation, and typeshare updates. Cover `mesh-peer-access / Nodes shows asymmetric access` (`nodes_shows_asymmetric_access`).
- [ ] 1.5 Preserve one-sided legacy consumption and guard the legacy wire entry points on an upgraded host. Cover `mesh-peer-access / Legacy sharing does not create a reverse grant` (`legacy_sharing_does_not_create_a_reverse_grant`), `mesh-peer-access / Failure does not trigger a legacy downgrade` (`failure_does_not_trigger_a_legacy_downgrade`), `mesh-peer-access / Legacy client needs explicit Full access` (`legacy_client_needs_explicit_full_access`), and `mesh-peer-access / Legacy wire format does not satisfy a Custom grant` (`legacy_wire_format_does_not_satisfy_a_custom_grant`). Test the protected methods and previously obtained references using a supported pre-upgrade binary.

## 2. Sessions, tools, and revocation

- [ ] 2.1 Guard lists, node/session RPCs, direct references and protected metadata. Cover `mesh-peer-access / Sessions off blocks an existing reference` (`sessions_off_blocks_an_existing_reference`).
- [ ] 2.2 Enforce allowed workspace operations and classify restricted execution. Cover `mesh-peer-access / Session sharing does not enable filesystem access` (`session_sharing_does_not_enable_filesystem_access`), `mesh-peer-access / Filesystem sharing preserves workspace confinement` (`filesystem_sharing_preserves_workspace_confinement`), `mesh-peer-access / Custom cannot include unsandboxed shell` (`custom_cannot_include_unsandboxed_shell`), and `mesh-peer-access / Full access does not add approval prompts` (`full_access_does_not_add_approval_prompts`). Use inert fixture commands and files in temporary workspaces.
- [ ] 2.3 Carry and recheck authenticated origin in live session responses, subscriptions, buffered turns, schedules, and same-host child work. Cover `mesh-peer-access / Revocation stops an attached peer without disconnecting others` (`revocation_stops_an_attached_peer_without_disconnecting_others`) `mesh-peer-access / A restricted peer cannot control a more privileged run` (`a_restricted_peer_cannot_control_a_more_privileged_run`), and `mesh-peer-access / Legacy sharing stops when Full access is removed` (`legacy_sharing_stops_when_full_access_is_removed`).
- [ ] 2.4 Enforce session sync fallback rules. Cover `remote-session-sync / Owner on an older version` (`owner_on_an_older_version`), `remote-session-sync / Second open from the same older owner` (`second_open_from_the_same_older_owner`), `remote-session-sync / Owner becomes unreachable mid-transfer` (`owner_becomes_unreachable_mid_transfer`), `remote-session-sync / Owner offline, window already local` (`owner_offline_window_already_local`), and `remote-session-sync / Confirmed denial cannot fall back to cached history` (`confirmed_denial_cannot_fall_back_to_cached_history`).

## 3. Provider grants and metering

- [ ] 3.1 Apply the same policy to catalog, contract, one-shot, stream setup and control, and hosted-session model dispatch. Cover `mesh-provider-quotas / Only the selected provider and models are usable` (`only_the_selected_provider_and_models_are_usable`), `mesh-provider-quotas / All models follows the host catalog` (`all_models_follows_the_host_catalog`), `mesh-provider-quotas / Host provider configuration is authoritative` (`host_provider_configuration_is_authoritative`), `mesh-provider-quotas / Session inference and direct inference share an allowance` (`session_inference_and_direct_inference_share_an_allowance`), and `mesh-provider-quotas / Provider revocation stops an active stream` (`provider_revocation_stops_an_active_stream`). Validate auxiliary requests, rerouting denial, and standalone `ProviderShare`.
- [ ] 3.2 Implement atomic reservations across provider and model scopes and qualify a supported finite binding. Cover `mesh-provider-quotas / Provider and model limits are independently binding` (`provider_and_model_limits_are_independently_binding`), `mesh-provider-quotas / Concurrent requests cannot overcommit quota` (`concurrent_requests_cannot_overcommit_quota`), `mesh-provider-quotas / Unbounded requests are not accepted on a finite grant` (`unbounded_requests_are_not_accepted_on_a_finite_grant`), and `mesh-provider-quotas / Unlimited inference needs no token bound` (`unlimited_inference_needs_no_token_bound`). Test exact Mtok conversion, invalid bounds, and transaction races without paid calls.
- [ ] 3.3 Implement peer-scoped attempt identity, durable settlement, recovery, and owner reset. Cover `mesh-provider-quotas / Streaming and one-shot usage settle once` (`streaming_and_one_shot_usage_settle_once`), `mesh-provider-quotas / Cancelled work without final usage is not free` (`cancelled_work_without_final_usage_is_not_free`), `mesh-provider-quotas / Restart and regrant do not top up an allowance` (`restart_and_regrant_do_not_top_up_an_allowance`), and `mesh-provider-quotas / Reset waits for outstanding attempts` (`reset_waits_for_outstanding_attempts`), `mesh-provider-quotas / Changing a cap preserves consumption` (`changing_a_cap_preserves_consumption`), and `mesh-provider-quotas / Changing a schedule requires explicit reconfiguration` (`changing_a_schedule_requires_explicit_reconfiguration`). Include finite/unlimited transitions, bound-violation and wrong-peer stream ownership checks.
- [ ] 3.4 Verify sequencing compatibility and peer-bound callbacks on supported legacy and upgraded paths. Cover `remote-stream-relay / Old host, new client` (`old_host_new_client`), `remote-stream-relay / New host, old client` (`new_host_old_client`), and `remote-stream-relay / Heartbeat during a held gap` (`heartbeat_during_a_held_gap`).
- [ ] 3.5 Implement UTC calendar windows, late settlement, scoped status and quota denial details. Cover `mesh-provider-quotas / Recurring windows renew at UTC calendar boundaries` (`recurring_windows_renew_at_utc_calendar_boundaries`), `mesh-provider-quotas / A stream spanning renewal settles against its original windows` (`a_stream_spanning_renewal_settles_against_its_original_windows`), and `mesh-provider-quotas / A quota denial identifies the relevant reset time` (`a_quota_denial_identifies_the_relevant_reset_time`). Use a controllable host clock; test leap and short months, Monday boundaries, downtime, rollback and mixed schedules without wall-clock waits.

## 4. ACP client contract

- [ ] 4.1 Carry owner authority from ACP ingress to capability discovery and each sharing handler. Cover `mesh-access-acp / ACP advertises sharing controls only to the host owner` (`acp_advertises_sharing_controls_only_to_the_host_owner`) through owner stdio and authorized/unauthorized WebSocket connections before session attachment.
- [ ] 4.2 Wire Nodes, peer readback, grant edits, cap edits/reconfiguration and scoped reset. Cover `mesh-access-acp / ACP separates saved local policy from unavailable remote access` (`acp_separates_saved_local_policy_from_unavailable_remote_access`), `mesh-access-acp / Owner manages sharing and quotas entirely through ACP` (`owner_manages_sharing_and_quotas_entirely_through_acp`), `mesh-access-acp / Stale and blocked ACP mutations are distinguishable` (`stale_and_blocked_acp_mutations_are_distinguishable`), and `mesh-access-acp / ACP wire payloads round trip for provider and model quotas` (`acp_wire_payloads_round_trip_for_provider_and_model_quotas`). Assert serialized keys, version rejection, exact token counters and machine-readable errors through ACP.
- [ ] 4.3 Deliver peer-scoped invalidations without session attachment and verify recovery through fresh reads. Cover `mesh-access-acp / A second ACP client refreshes after sharing changes` (`a_second_acp_client_refreshes_after_sharing_changes`) and `mesh-access-acp / ACP recovers current peer access without notification replay` (`acp_recovers_current_peer_access_without_notification_replay`). Use two owner clients and a non-owner connection to verify recipient scope.
