# Proposal

## Why

Lean 4 is widely used for theorem proving and formal verification (Mathlib, Lean core, verified-software projects), but the `index` tool rejects `.lean` files. Agents working in Lean repositories therefore fall back to full-file reads, and the symbol tools (`get_symbol`, `get_function`, `replace_symbol`, `find_symbol_references`) and the repository knowledge code records cannot address Lean declarations at all. Lean files are long and declaration-dense, so a structural outline saves the most tokens there.

## What Changes

- Add Lean 4 (`.lean`) to the shared symbol-extraction pipeline, using the upstream grammar `Julian/tree-sitter-lean`. It is pinned by git revision because it is not published on crates.io. Its Rust binding uses `tree-sitter-language`, so it is compatible with the tree-sitter 0.26 runtime already in use. The crates.io `tree-sitter-lean4` fork requires tree-sitter 0.25 and cannot coexist with 0.26 because of the `links = "tree-sitter"` key.
- New Lean extractor that maps declarations to symbol kinds:
  - imports, `open`/`export` → imports
  - `namespace` → module, with its declarations as children
  - `def`/`abbrev`/`opaque` and `theorem`/`lemma` → functions
  - `instance` → impl
  - `structure` → struct, and `class` → trait, both with field children
  - `inductive` → enum, with constructor children
  - `axiom`/`constant` → constants
  - `example` → tests
  - `macro`/`syntax`/`notation`/`macro_rules`/`elab_rules` commands → macros
- Rebuild scope from the grammar's flat `namespace`/`section`/`mutual`/`end` markers:
  - Namespaces nest their declarations as children, and qualified names use Lean's dotted form (`Nat.add_comm`).
  - Sections and `mutual` blocks are transparent.
  - A namespace left unclosed runs to the end of the file.
- Outline layout for Lean:
  - Namespaces appear in the `namespaces` section, with their members nested under them rather than copied into kind sections.
  - Top-level theorems and lemmas appear in a new `theorems` section.
  - Both rules apply only to Lean, so outlines for other languages are unchanged.
- Extend the extension→language map and the `index` tool description and unsupported-extension error to include Lean.

## Non-goals

- Semantic Lean understanding. Elaboration, macro expansion, resolution of `open` scopes, or recognition of user-defined notation would require the Lean toolchain or LSP.
- Doc-comment extraction, `variable`/`universe`/`set_option`/`#check`/`#eval` symbols, and tactic-level structure.
- Similarity and duplicate detection (`function_index`) for Lean. This remains limited to Rust and Python.
- Publishing or forking the grammar. A follow-up may switch to a crates.io release if upstream publishes one.
- A cargo feature gate for the grammar. It is always compiled, like the other grammars.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `index-tool`: changes to existing requirements:
  - `lean` joins the supported extensions.
  - A Lean outline requirement is added, covering namespace nesting and the `theorems` section.
  - The "new sections do not alter existing languages" guarantee is extended to the `theorems` section.
  - The tool description and the unsupported-extension error must list Lean.

## Impact

- **Packages**:
  - `querymt-agent-index`:
    - new `symbol_index/extractors/lean.rs`
    - dispatch in `symbol_index/extractors/mod.rs`
    - extension map in `outline_index/common.rs`
    - Lean-only routing in `symbol_index/outline_projection.rs`
  - `querymt-agent-services`: `index` tool description, error string and tests (`tools/builtins/index.rs`).
  - `querymt-agent-knowledge`: no code change. `.lean` files now yield symbol records instead of `Unsupported` path-only records.
  - `querymt-workspace-hack`: regenerated by hakari.
- **Feature flags**: none.
- **Public Rust API**: `querymt_agent_index::symbol_index::outline_projection::symbols_to_sections` gains a `language: &str` parameter. **BREAKING** for direct callers of this function; the only caller is `outline_index::extractors::extract_outline`.
- **Dependencies**:
  - New git dependency `tree-sitter-lean` (Julian/tree-sitter-lean, pinned revision) plus its build dependency `cc`; `tree-sitter-language` is already in the lockfile.
  - The generated `parser.c` is about 49 MB, so expect a noticeable increase in clean-build time for `querymt-agent-index` and its dependents.
  - The upstream repository is about 190 MB, which affects cargo and Nix git fetches. `flake.nix` already allows git dependencies (`allowBuiltinFetchGit = true`).
- **Tool behavior**:
  - `index`, `get_symbol`, `get_function`, `find_symbol_references` and `replace_symbol` accept `.lean` files.
  - This is an additive tool-behavior change and gets a CHANGELOG "Unreleased → Added" entry.
  - No config, hook, middleware, ACP, typeshare, session DB, Extism or Python-binding changes.
- **querymt-desktop follow-up**: none.
